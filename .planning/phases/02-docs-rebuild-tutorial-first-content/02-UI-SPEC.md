# Phase 2 — UI Design Contract

> Visual and interaction contract for the docs content rebuild. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope framing:** this is a CONTENT phase on a locked visual shell. The design system is Phase 1's output (`design/tokens.css` `--jv-*` + `src/styles/starlight-tokens.css` `--sl-*` remap) and is NOT re-opened here — zero new colors, zero new fonts, zero new CSS files. What this contract locks is: (1) the layout/structure of the new pages, (2) Starlight component usage conventions (Tabs, asides, code blocks), (3) the quickstart success/failure rendering pattern, and (4) the copywriting contract. Visual identity refinement is Phase 3.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — Starlight 0.37.7 built-in components only (`Tabs`, `TabItem`, asides, expressive code) |
| Preset | not applicable (no shadcn; Astro/Starlight, not React) |
| Component library | `@astrojs/starlight/components` — no third-party UI packages, no new dependencies (locked by 02-RESEARCH: Phase 2 adds ZERO packages) |

**Hard rule:** no page in this phase may introduce a `<style>` block, inline style, or new CSS file inside `src/content/docs/`. If a layout need cannot be met by Markdown/MDX + Starlight built-ins, it is flagged to the planner, not hand-styled. (Exception: `public/brand-logo.html`'s D-01 `@font-face` block — a passthrough file outside the docs shell, spec'd verbatim in 02-RESEARCH Code Example 5.)

## Spacing Scale

No new spacing tokens. All docs pages inherit Starlight's content rhythm (its `--sl-*` spacing engine, untouched by the Phase 1 remap). Declared here for the checker's reference as the *effective* scale, all inherited:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Starlight inline code padding (inherited) |
| sm | 8px | Table cell padding (inherited) |
| md | 16px | Paragraph/list rhythm — Starlight `1rem` content flow (inherited) |
| lg | 24px | Aside and code-block margins (inherited) |
| xl | 32px | Between-section gaps under `##` headings (inherited) |
| 2xl | 48px | not used this phase |
| 3xl | 64px | not used this phase |

Exceptions: none. Content authors control spacing only through document structure (heading levels, paragraph breaks), never through CSS.

## Typography

All inherited from Starlight defaults + the Phase 1 token remap (`--sl-font: var(--jv-sans)`, `--sl-font-mono: var(--jv-mono)`). No size or weight overrides this phase.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`--sl-text-base`, inherited) | 400 | 1.75 (Starlight content default, inherited) |
| Code (inline + blocks) | ~15px (`--sl-text-code`/`--sl-text-code-sm`, inherited) | 400 | 1.65 (inherited) |
| Heading (`##`/`###`) | Starlight scale (inherited) | 600 | 1.2 (inherited) |
| Page title (`title` frontmatter) | Starlight h1 scale (inherited) | 600 | 1.2 (inherited) |

**Structural typography rules (the part content authors actually control):**
- Every page: frontmatter `title` + `description` only (established pattern; `title` is MANDATORY — a missing title silently drops the page from the production build, Phase 1 lesson).
- No duplicate H1 in the body when `title` renders one — the changelog import (D-15) keeps frontmatter `title: Changelog` and drops the source's `# Changelog` H1, consistent with the other pages.
- Heading depth cap: `##` for steps/sections, `###` for sub-points. Never `####` — if a page needs 4 levels it is restructured or split.
- Inline code in backticks ALWAYS for commands, paths, tool names, flags, JSON keys (project convention, CLAUDE.md).
- Tool names render in their real camelCase (`goToDefinition`, `semanticSearch`) — matching sidebar labels and server truth; page slugs stay kebab-case (WR-01 class of bug: link *targets* are kebab-case, link *labels* are camelCase).

## Color

All colors come from `design/tokens.css` — no new values, no hex literals anywhere in this phase's output. 60/30/10 mapping of the existing tokens as consumed by Starlight:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--jv-bg)` (#f3f7fa light / #040506 dark) | Page background via `--sl-color-bg` |
| Secondary (30%) | `var(--jv-surface)` + `var(--jv-border)` | Code-block/table surfaces, sidebar, borders (Starlight-derived) |
| Accent (10%) | `var(--jv-accent)` (#29527d light / #5b86b7 dark) | via `--sl-color-accent` — see reserved list |
| Destructive | Starlight built-in `danger` aside palette (not remapped, intentionally) | `:::danger` asides only |

Accent reserved for: content links, current-page sidebar item, active `TabItem` indicator, `:::tip`/`:::note` aside accents (all Starlight-native consumers of `--sl-color-accent`). Content NEVER invokes accent directly — no colored text, no badges, no custom callout styling.

Semantic aside colors (Starlight built-ins, used as-is): note=accent-blue, tip=accent, caution=orange, danger=red. These are the ONLY additional colors that appear, and only through the four aside directives.

## Copywriting Contract

Voice baseline: the existing quickstart's direct, second-person tone ("Install the external binaries…", "You'll know it works when…") for all journey content; **terse reference voice** for tool/CLI pages per D-06 — signature, params table, one example, done. Limitations are stated as settled decisions with rationale inline, never TODOs (project convention + D-08).

| Element | Copy |
|---------|------|
| Primary CTA (quickstart step 1) | The `setup.sh` curl command, verbatim canonical URL only: `curl -fsSL https://raw.githubusercontent.com/jarvis-intelligence/jarvis-index/main/setup.sh \| sh` (D-09; never a variant URL — security row in 02-RESEARCH) |
| Success shape label (quickstart only, D-07) | Bold literal phrase **"You'll know it works when…"** followed by the expected-output code block — same phrase at every step, greppable (DOCS-10 validation greps for it) |
| Failure shape label (quickstart only) | Bold literal phrase **"You'll know it broke when…"** followed by the real failure shape + one sentence linking the matching troubleshooting entry |
| Empty state (404 lookup table, zero retires) | Heading: "Page not found". Table placeholder row/line: "No URLs have been retired yet — the page you wanted may have moved; find it in the sections below." + links into the six nav groups |
| Error state (tool reference pages) | The `{"error": "..."}` contract itself, quoted verbatim from real transcripts (D-05/D-07) — no invented messages, no extra callouts on the 9 tool pages |
| Error state (troubleshooting) | Fixed three-part structure per entry: **Symptom** (what you see, verbatim) → **Diagnosis** (why) → **Fix** (exact command), per D-13 |
| Destructive action (`jarvis forget`) | Its CLI page states irreversibility as fact in one sentence ("removes the index permanently; re-run `jarvis index` to rebuild") — no confirmation UI exists in a static docs site |
| semanticSearch caveat (D-08) | `:::caution` aside as the FIRST element after the page intro sentence: requires the `[semantic]` extra AND a second MCP server registration; framed as a settled decision with the `--python 3.13` pin workaround, never "coming soon" |

## Starlight Component Conventions

### Tabs (per-client steps)
- Component: `<Tabs syncKey="client">` from `@astrojs/starlight/components` — requires `.mdx` (quickstart renames `.md`→`.mdx`, URL unchanged).
- **Canonical TabItem set — identical labels and order on every tab group site-wide:** `Claude Code`, `Cursor`, `Codex CLI`, `Any stdio client`. The shared `syncKey="client"` makes the reader's choice persist across groups and pages; label drift breaks the sync, so this list is locked.
- Used in exactly two places this phase: quickstart "register per client" step, install-matrix walkthrough. Nowhere else — reference pages stay linear (D-06).

### Asides (callouts)
| Directive | Reserved for | This phase's instances |
|-----------|--------------|------------------------|
| `:::note` | Neutral context the reader may skip | sparing use |
| `:::tip` | Optional extras (existing `[semantic]`/`[watch]` extras pattern) | quickstart optional-extras block (already exists) |
| `:::caution` | Settled-decision caveats + quickstart failure shapes that need visual weight | semanticSearch page top caveat (D-08); Kotlin/Android auto-degrade notes on requirements page |
| `:::danger` | Data-loss / irreversible only | none expected (jarvis forget's one-liner doesn't warrant a box) |

Budget: max ONE aside per tool reference page (D-07 says the 9 tool pages get no extra success/failure callouts — the semanticSearch caution is the sole exception, mandated by D-08). Journey pages: asides only where the table above assigns them.

### Code blocks
- Every block carries a language tag: `sh` for terminal commands, `json` for payloads/configs, `toml` where applicable.
- Config-file contents get a `title` attribute naming the file (e.g. ```json title=".mcp.json"); terminal commands get no title.
- JSON examples: verbatim shapes from 02-RESEARCH Product Truth §1–2 ONLY — flat freshness fields, nested `range` locations. Any example containing `startLine`/`startColumn` on a nav tool or a nested `"freshness": {` object is a contract violation (Pitfall 2). `semanticSearch` result entries legitimately use `startLine`/`endLine`.
- No line highlighting, no diff syntax, no collapsible sections this phase — plain frames keep the copy surface honest.

### Tables
- Tables are the decision-surface primitive (project convention): install matrix, registry deep links, language matrix, params tables on all 9 tool pages, troubleshooting symptom tables, 404 lookup.
- Tool-page params table columns (uniform across all 9): `Parameter | Type | Required | Description`.
- Commands/URLs inside table cells stay in backticks; Starlight's built-in horizontal scroll handles mobile overflow — no manual truncation.

### Links
- All internal links authored docs-root-relative in trailing-slash form (`/tools/find-references/`) so `rebaseDocsLinks()` rebases to the canonical URL with no 301 hop (Pitfall 3). WR-01 (`/tools/findReferences`) is fixed in the content pass.

## Quickstart Step Pattern (DOCS-10 rendering contract)

Each of the five steps (why → setup.sh → `jarvis index` → register per client → first tool call) renders as:

```
## Step N: {imperative title}
{1–2 sentences, second person}
{command code block, sh}
**You'll know it works when…**
{expected output code block — real transcript per D-05}
**You'll know it broke when…**
{real failure shape} + one sentence → link to the matching troubleshooting entry
```

- Bold-label + code-block, NOT asides — keeps the aside budget for caveats and makes both phrases greppable (the DOCS-10 validation command greps for them).
- "Register per client" step swaps the single command block for the canonical `<Tabs syncKey="client">` group; the works/broke pair still follows, client-agnostic.
- The requirements link ("check your language is supported" → `/guide/requirements/`) sits immediately before the install step's command block (D-14).
