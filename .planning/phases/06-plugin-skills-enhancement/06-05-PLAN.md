<objective>
Adopt `claude plugin validate --strict` as a sixth, vendor-supplied guard — pinned, placed after the
repo's own hermetic assertions, and documented as a supplement rather than a replacement.

Purpose: research measured that this is the only tool that catches hooks-schema drift, emitting an
unknown-hook-event finding and exiting 1 on a wrong event name. Plan 06-03 ships two hook files whose
schemas differ by one character of casing; nothing else in this repo can tell them apart. The same
research measured that the validator does **not** report unknown frontmatter keys, so it cannot stand
in for dimension P4.

Output: a pinned `@anthropic-ai/claude-code` install step and a `Validate plugin + marketplace` step
in the existing `manifest-checks` job, gated behind a human verification of the package itself.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry → CI runner | `Install Claude Code CLI` fetches and globally installs a third-party package, with its install scripts, into the job's environment |
| vendor CLI → CI verdict | `claude plugin validate` decides whether the job passes; its warning set can change between vendor releases |
| repository content → vendor CLI | the validator reads every manifest, hook file, skill, command, and agent in the checkout |

| T-06-25 | Denial of Service | a vendor release changing warning text and failing `--strict` with no repo change | medium | mitigate | The exact-version pin removes the drift channel entirely; the two hermetic Node guards run first, so this repo's own invariants are never masked by the vendor step |
| T-06-26 | Repudiation | reading a green vendor validation as proof of frontmatter conformance | high | mitigate | Measured false: the validator reports no unknown SKILL.md, command, or agent frontmatter key.
