<objective>
Turn the skills' prefer-jarvis rule from advice into enforcement: ship a SessionStart hook that tells
the agent, at session start, when the current repository's jarvis index is stale or missing — and that
is completely silent otherwise.

Purpose: `plugin/skills/jarvis-use/SKILL.md:43-53` asks the agent to check `getIndexStatus` before
every structural call. Nothing makes it. The staleness signal already exists server-side
(`../jarvis/src/jarvis/server.py:587-589`); the hook surfaces it once, cheaply, at the only moment the
agent can still act on it.

Output: one POSIX `sh` probe script, two client-shaped hook configs, the single Cursor manifest
declaration, and a `plugin/README.md` that states the Codex trust caveat honestly and carries the
0.9.1 floors.
</objective>
