## Spacing Scale

Declared values (multiples of 4). Sources: existing `landing.css` classes and `tokens.css` custom properties.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps (`brand` gap 0.7rem ≈ 11px uses this for inner icon spacing), dot separators (hero-meta `.dot` 3px ≈ xs) |
| sm | 8px | Compact element spacing (`surfaces` gap 0.5rem), inline padding |
| md | 16px | Card padding (1.5rem = 24px, between md and lg; see exceptions), section internal gaps |
| lg | 24px | Section-head gap (1.5rem), card padding (1.5rem), table cell padding (1rem horizontal) |
| xl | 32px | Hero-side padding-left (2rem = 32px), section-head gap on desktop (2.5rem) |
| 2xl | 48px | Section padding-block mobile (3rem), hero-frame gap (2.5rem) |
| 3xl | 64px | Section padding-block desktop (5rem/6.5rem), hero min-height (42rem) |

Exceptions:
- `.section` padding-block: 5rem (80px) mobile, 6.5rem (104px) desktop — page-level vertical rhythm, not multiples of 4 but intentional visual breathing
- `.mono-box` min-height: 3.35rem (54px) — touch-target minimum for the click-to-copy chip
- `.hero-art` mask uses percentage-based gradient stops (14%), not spacing tokens

- NOT used for: body text, card backgrounds, muted labels, table borders

### Token Refinements (Claude's Discretion — CONTEXT.md)

Phase 3 MUST refine the existing `--jv-*` tokens in place (not fork). Specific refinements:

1. **Tokenize `#9aa4ac`** (appears in `landing.css:374,404,414` — `.mono-box .copy` idle color, `.exchange-head` color, `.exchange-body .ex-out` color). New token: `--jv-muted-soft` (a lighter muted for terminal UI chrome).
   - Light: `#9aa4ac` (current literal)
   - Dark: derive a darker variant (e.g. `#5a6168`) that passes 4.5:1 contrast against `--jv-chip-bg` (`#0a0e11`)

2. **Tokenize `#000`** (appears in `landing.css:240-241` — `.hero-art` mask-image gradient stops). New token: `--jv-mask-opaque` set to `#000` in both themes (mask color is not visible; the value is structurally opaque black regardless of theme).

3. **Dark-mode contrast pass**: verify `--jv-muted` (`#8c9399` on `#040506`) meets WCAG AA for normal text (4.5:1). If not, bump dark `--jv-muted` toward `#969da3`. Verify `--jv-accent` (`#5b86b7` on `#040506`) meets 3:1 for large text/interactive elements.

4. **Accent punch** (Claude's Discretion): evaluate whether `--jv-accent-strong` dark value (`#7cafe4`) provides sufficient visual energy for CTA buttons and diagram highlights. If too soft, increase saturation or shift toward `#8ec0f0`.

## Section Specification

### 1. Hero
- **Structure**: Two-column grid on desktop (existing `.hero-frame` pattern), single-column on mobile
- **Left column**: h1 (one-line value prop, Claude's Discretion wording), tagline (1-2 sentence expansion), lede (supporting detail), compact tabbed install widget (`.mono-box` for default Installer+uv tab showing the curl command, clickable to copy)
- **Right column**: hero-art decorative SVG (keep existing, retokenize `#000` mask)
- **Below hero content**: meta line (MIT license, macOS/Linux, open source) — existing `.hero-meta` pattern
- **Widget sync**: `syncKey="channel"` connects hero widget to quickstart widget

### 2. Demo Panel
- **Structure**: Stepper UI with 3 preset steps
- **Each step**: (a) natural-language question, (b) MCP tool call JSON (input), (c) recorded result JSON (output)
- **JSON shapes**: Reuse verbatim from Phase-2 quickstart transcripts (getIndexStatus lines 178-200, goToDefinition lines 209-224, findReferences from tool reference page)
- **Interaction**: Click step indicator or prev/next to navigate. Deliberately not live — these are recorded fixtures
- **Styling**: Reuse `.exchange` / `.exchange-head` / `.exchange-body` terminal-chrome pattern

### 3. 9-Tool Tiered Showcase
- **Structure**: `.card-grid` with `.cols-3` on desktop (3-column), 2-column on tablet, single-column on mobile
- **7 plain tools** (no gate chip): `getIndexStatus`, `goToDefinition`, `findReferences`, `callHierarchy`, `documentSymbols`, `searchCode`, `blastRadius`
- **2 gated tools** (gate chip appended to card):
  - `semanticSearch` — gate chip: "requires `[semantic]` extra + reindex" → deep-link to `guide/requirements/` semantic anchor
  - `typeHierarchy` — gate chip: "requires fork-built scip + reindex" → deep-link to `guide/requirements/#swift-version-floor-and-code-signed-targets` or relevant scip anchor
- **Each card**: `.card-kicker` (mono, uppercase — tool name), h3 (human-readable name), p (one-line description), gate chip appended for the 2 gated tools
- **Gate chip**: `.gate-chip` with warning styling (amber/warm tone distinct from accent), containing gating text and a link to the requirements.md anchor

### 4. Language Matrix
- **Structure**: `.table-wrap` containing a `<table class="table-matrix">`
- **Content**: Mirrors `guide/requirements.md` matrix exactly — 14 rows (TypeScript/TSX, Python, Java/Kotlin, Swift, Go, Ruby, Rust, C, C++, C#, PHP, Scala, shell, SQL), 3 columns (Language, Navigation, Caveat)
- **Navigation column**: ✅ Yes for 4 families, — for 10 search-only
- **Caveat column**: Links to the same `###` anchors in requirements.md as the docs page (Android/Gradle, Kotlin version, Maven on macOS, Swift version floor)
- **Mobile**: Contained horizontal-scroll region (`.table-wrap` with `overflow-x: auto`), no page-level horizontal scroll

### 5. Local-First Privacy
- **Structure**: Single-column prose section with `.section-head` (title + lede) and supporting content
- **Content**: "Nothing leaves your machine" positioning — all computation local, no telemetry, no network, no cloud
- **Styling**: May reuse `.note` pattern for a highlighted callout, or a dedicated layout with inline SVG icons

### 6. Architecture Diagrams
- **Structure**: Two diagrams in `.diagram-wrap` containers
- **Sources**: `../jarvis/docs/assets/jarvis-layers.dot` (7-layer architecture) and `../jarvis/docs/assets/jarvis-index-pipeline.dot` (index pipeline with failure semantics)
- **Rendering**: Inline SVGs whose `fill` and `stroke` attributes reference `--jv-*` CSS variables (or classes that resolve to them via existing `.diagram` styles). No hardcoded hex colors. No external SVG files. No CSS `filter` hack for dark mode — the SVGs must natively adapt via the variable-driven classes
- **Diagram node colors**: Map the .dot source's semantic groups to `--jv-*` tokens:
  - Runtime cluster: `--jv-accent` family (blues)
  - Storage seam: `--jv-accent-soft` / warm neutral
  - Indexing cluster: distinct green tone (new token `--jv-diagram-green` or reuse `color-mix`)
  - Failure terminal: warm red tone (new token `--jv-diagram-red` or reuse `color-mix`)
- **Caption**: `.caption` class below each diagram

### 7. Badges + Final CTA
- **Structure**: `.closing` grid (existing 2-column pattern on desktop)
- **Left**: Final CTA heading + text-link to docs
- **Right**: Row of 4 inline SVG badges (GitHub, PyPI, MIT, MCP Registry)
- **Badge spec**: Each badge is a self-contained inline SVG. Colors reference `--jv-*` tokens. No external image fetches. Badge layout: icon + text, pill-shaped or rectangular with rounded corners matching `--jv-radius`

### 8. Footer
- **Structure**: Existing `.site-footer` / `.footer-inner` pattern, updated links
- **Links**: MIT, GitHub (repo), PyPI (package), MCP Registry (`io.github.jarvis-intelligence/jarvis`), Discussions (GitHub Discussions), Docs (`/docs/`)

## Theme Contract

- Theme toggle mechanism: `starlight-theme` localStorage key + `data-theme` attribute on `<html>` — MUST survive the rebuild unchanged (CONTEXT.md)
- Anti-FOUC script: inline `<script is:inline>` in `<head>` reads `starlight-theme` from localStorage and sets `data-theme` before first paint — MUST survive
- `design/tokens.css`: single source of truth for all colors. Light defaults in `:root`, dark overrides in `[data-theme='dark']`
- `src/styles/starlight-tokens.css`: remaps `--jv-*` onto Starlight's `--sl-*` for the docs surface — not touched by this phase
- Dark-mode contrast pass REQUIRED: verify all foreground/background pairs meet WCAG AA (4.5:1 for normal text, 3:1 for large text/interactive) — especially `--jv-muted` on `--jv-bg` in dark mode
- Diagram SVGs: must render correctly in both themes without CSS `filter` hacks — use CSS variable-driven `fill`/`stroke` attributes or CSS class references that resolve via the `.diagram` styles
