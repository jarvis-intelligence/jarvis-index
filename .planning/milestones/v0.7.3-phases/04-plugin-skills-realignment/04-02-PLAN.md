# 04-02: Release Protocol — Manifest Bump, Validation, Tag

## Objective

Bump all three plugin manifests from `0.7.2` to `0.7.3` with updated descriptions incorporating "structural code intelligence" (SKIL-02), validate with `check-manifests.mjs` and the Cursor marketplace validator, then create and push git tag `v0.7.3`. The tag must be created and pushed AFTER validation passes because the docs links in plan 04-01 resolve at that tag (CONTEXT.md). This is the definition-of-done plan: after it, the release is shippable and verifiable.

## must_haves

### truths

- `plugin/.claude-plugin/plugin.json` top-level `version` is `"0.7.3"`
- `plugin/.cursor-plugin/plugin.json` top-level `version` is `"0.7.3"`
- `.codex-plugin/plugin.json` top-level `version` is `"0.7.3"`
- All three manifest `description` fields contain "structural code intelligence" (the settled voice per CONTEXT.md, replacing the prior "SCIP code navigation and Zoekt search" phrasing)
- `node scripts/check-manifests.mjs` exits 0 and prints the agreement message
- `diff plugin/.mcp.json plugin/mcp.json` produces empty output (byte-identical — neither file is touched in this phase)
- `--from jarvis-mcp>=0.6.0` appears in both `plugin/.mcp.json` and `plugin/mcp.json` unchanged (floor preserved per CLAUDE.md)
- Git tag `v0.7.3` exists locally
- Git tag `v0.7.3` is pushed to origin (verifiable via `gh api repos/jarvis-intelligence/jarvis-index/git/refs/tags/v0.7.3` returning 200)
- `setup.sh` is never edited (ownership rule)
- Marketplace files (`.claude-plugin/marketplace.json`, `.cursor-plugin/marketplace.json`) are not edited (carry no version per CONTEXT.md)
- `plugin/.mcp.json` and `plugin/mcp.json` are never edited (no MCP config changes per RESEARCH §5)
