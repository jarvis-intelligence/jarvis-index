Pipeline

Index locally, query locally.

A language indexer emits SCIP protobuf. jarvis index converts it to SQLite and builds the Zoekt index. jarvis-server answers over stdio. Every arrow runs on your machine.

No step in this pipeline contacts a network service.

Tools

Nine MCP tools, grouped by what you are asking.

Each takes repo — the slug produced by jarvis index.

Navigate

documentSymbols

Every top-level symbol in a file, each with its range.

goToDefinition

Resolve a symbol's definition site or sites.

findReferences

Every occurrence of a symbol.

callHierarchy

Single-level incoming and outgoing calls.

typeHierarchy

Supertypes and subtypes.

Search

searchCode

Lexical search via Zoekt, on a lazy-started webserver.

semanticSearch

Vector, Zoekt, and SCIP symbol-definition hybrid, fused by reciprocal rank.

Cross-repo and status

blastRadius

Two-hop package-dependency breadth-first search across indexed repos.

getIndexStatus

Whether a repo has a published index, and how fresh it is.

One caveat worth knowing up front. semanticSearch needs the [semantic] extra, and the plugin's default MCP registration deliberately omits it so cold start stays free of lancedb and torch. Using it means registering a second, differently-named server — jarvis-semantic.

Install

Three clients, one plugin directory.

Claude Code

/plugin marketplace add jarvis-intelligence/jarvis-index /plugin install jarvis@jarvis

Codex CLI

codex plugin marketplace add https://github.com/jarvis-intelligence/jarvis-index --ref main codex plugin add jarvis

Cursor

Cursor exposes no CLI for adding a marketplace. On Teams or Enterprise: Dashboard → Plugins → Add Marketplace → Import from Repo. On any plan, symlink the plugin directory:

ln -s "$PWD/jarvis-index/plugin" ~/.cursor/plugins/local/jarvis

Then, on every client

Install the external binaries, then index a repo. setup.sh fetches seven dependencies into ~/.jarvis/bin, verifies each tarball's SHA256, and skips whatever is already present.

jarvis index /path/to/repo

Why jarvis ships a patched scip

Upstream scip through v0.9.0 never populates global_symbols.relationships, which makes typeHierarchy unanswerable. jarvis builds from a fork carrying the fix and hosts the binary itself.

The exit ramp is written down: when upstream merges the fix and cuts a release, jarvis repoints at it and deletes the build pipeline. A patched dependency is a liability to be retired, not a moat.

Local-first

Four claims, each with the mechanism that enforces it.

These are checkable rather than promised.

ClaimEnforcement
No telemetry, no analyticsNo analytics code, and no outbound calls during queries.
The only network egress is the wheel fetchuvx on first server start, plus a one-time embedding-model download if you install the [semantic] extra.
Indexes are read-onlyOpened mode=ro&immutable=1.
Dependencies are pinned and verifiedExact commit or tag pins, each with a written justification; every tarball SHA256-verified before install.

Roadmap

What is next Not shipped

Nothing below is available today, and none of it carries a date.

Near term, local

  • A public Cursor marketplace listing.
  • Swift indexing on Intel Macs, via an x86_64 scip-swift asset.
  • setup.sh --verify, to self-diagnose PATH shadowing and pin mismatches.

jarvis Cloud, opt-in

  • Hosted indexing.
  • Team index sharing — index once in CI, teammates pull instead of each re-indexing.
  • Enterprise self-hosted, as a deployment mode of the same thing.

Local stays the default. Cloud is opt-in and never required — the guarantees above describe how jarvis behaves on your machine, and that does not change.
